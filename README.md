## 📊 Что оцениваем

### Проверка фактов

При работе с утверждениями различаем три случая:

- **SUPPORTED** — утверждение подтверждено источником.
- **CONTRADICTED** — источник прямо противоречит утверждению.
- **NOT_ENOUGH_INFO / UNSUPPORTED** — доступных сведений недостаточно для проверки. Это не равно доказанной ложности.

### Качество RAG с помощью RAGAS

| Метрика | Что показывает |
|---|---|
| **Faithfulness** | Подтверждаются ли факты ответа найденным контекстом; ключевая метрика при анализе галлюцинаций |
| **Factual Correctness** | Соответствие ответа эталонным фактам |
| **Response Relevancy** | Насколько ответ релевантен вопросу |
| **Context Precision** | Насколько удачно поиск ранжирует полезные фрагменты |
| **Context Recall** | Достаточно ли извлечено информации для эталонного ответа |
| **Semantic Similarity** | Близость ответа и эталона по смыслу |

В локальных версиях расчёт LLM-метрик может занимать больше времени. **Высокая Faithfulness означает согласованность с извлечённым контекстом, а не доказанную истинность фактов в мире.**

### Качество LLM-судьи

Участники проектируют промпт со **шкалой 0–4** и выбирают порог, при котором ответ считается корректным. Затем сравнивают решения LLM-судьи с разметкой датасета:

- **Accuracy** — доля правильных классификаций.
- **Precision** — какая доля обнаруженных галлюцинаций действительно является ошибками.
- **Recall** — какая доля всех галлюцинаций была обнаружена.
- **F1-score** — баланс Precision и Recall.
- **Confusion Matrix** — ложные срабатывания и пропущенные ошибки.

Порог следует подбирать на **DEV**, а итоговое качество измерять на **TEST**. Эталонные метки не должны передаваться LLM-судье при оценке.
